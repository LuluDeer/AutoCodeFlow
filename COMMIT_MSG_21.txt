docs(release): 固化 PyPI Trusted Publishing 登记参数 + 更新已过时的发版清单

v1.5.0 发版实证：publish-pypi 失败

    Trusted publishing exchange failure: invalid-publisher:
    valid token, but no corresponding publisher

根因不是配置写错：`a4dad9b` 在工作流里完成了 OIDC 迁移（删 password、加
id-token: write），但 Trusted Publisher 的**仓库外登记从未做**。该 commit 注释
里自己写了这是「发布前唯一待办的外部手动步骤」——但 commit message 不是清单，
没人会翻，于是直到第一次真正走 OIDC 发版（v1.5.0）才爆。v1.4.3 及以前走
`secrets.PYPI_API_TOKEN`，所以这个缺口一直被掩盖。

本次只补"让缺口可见"，不改发布凭证形态（仍走 OIDC）：

1. docs/release-checklist.md 新增「4.2.1 PyPI 发布凭证」：登记路径 + 逐字参数
   表格（含两个易错点：workflow name 只填 release.yml 不带目录前缀；
   environment 必须填 release，因为本 job 有 environment: release，OIDC
   claims 的 sub 因此带 :environment:release，PyPI 侧留空即不匹配）。
2. 同清单 4.2 节更新：v1.5.0 实测自动化已打通（release-please 卡点解除后，
   合并 Release PR 即自动打 tag 并触发 release.yml），删掉已废弃的
   「人工 tag 仍是主路径」「手工补建 GitHub Release」等过时步骤。
3. release.yml 注释固化登记参数，并修正原注释的误导性断言——原文称
   「未登记时会以明确报错失败」，实际 invalid-publisher 报错**不指向**登记
   缺失，只能靠 OIDC claims 反推，排查成本很高（v1.5.0 实证）。

另记回退路径：secrets.PYPI_API_TOKEN 仍在仓库中（2026-09-04 创建），登记未
完成时可在 Publish 步骤临时加回 `password:` 先发版。

验证：YAML 解析通过；本次仅注释与文档改动，不影响发布流程行为。
