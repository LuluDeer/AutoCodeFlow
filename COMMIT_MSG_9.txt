fix(executor): uv 缺失遮蔽解释器归因，node 报 unknown 而 python 报 interpreter_unavailable（EXP-02）

缺陷（routes/execute.ts 的 ensurePythonVenv）：任务声明了 Python 版本时，建 venv
分支原先**先** `resolveUvForExecute()`、**后** `ensureInterpreter(declaredVersion)`。

在一台既没装 uv、任务又声明了 Python 版本的执行器上，抛出的永远是
  「uv is not available on this executor (no UV_BIN, not on PATH, ...)」
该文案既不含 `解释器 <X.Y> 无法获取` 骨架，也不匹配 prepareFailureReason 的
解释器规则（那条要求 `No interpreter found` / `No download found` /
`Python downloads are set to manual` / `解释器…无法获取`），于是落到最后兜底
**`unknown`**——而 **python 执行器在同一情形下报 `interpreter_unavailable`**。

后果不是"文案难看"而是**分类语义丢失**：
  · 执行详情页失败分类、Dashboard 失败榜、重试策略表都以 failureReason 分流；
  · 运维按 interpreter_unavailable 筛"该预填/下载解释器的机器"时，node 上的
    这类失败全部落进 unknown 桶，**被筛掉**；
  · 同一失败在两个执行器上归类不同，与 A3 协议契约的「四端一致」直接冲突。

修法：把 `ensureInterpreter(declaredVersion)` 提到 uv 解析**之前**。
`ensureVersion()` 走解释器池/下载器，**不需要 uv**，提前即得到更准确归因：
池里没有且下不下来 → interpreter_unavailable（附「候选执行器」快照供调度改派）；
池里有 → 再解析 uv，此时 uv 缺失才是真正根因。无版本分支仍照旧先解析 uv。

连带（ADR-005：源码改动与内嵌产物同 commit）：execute.ts 进 ncc 内嵌 bundle，
已重打 apps/executor-desktop/executor-node-bundle.sha256（2474kB → 2475kB）。

验证：executor-node 676 passed / 7 skipped / 33 suites；tsc --noEmit 0 error；
eslint 0 error；桌面端 renderer selftest 不受影响。
反证 6 条（src/routes/exp02-uv-interpreter-order.spec.ts）：
  · 前 3 条用**真实的 prepareFailureReason** 证明两条文案确实归到不同分类
    （uv 缺失 → unknown；解释器缺失 → interpreter_unavailable），这是"顺序颠倒
    就丢归因"的量化依据；
  · 后 3 条钉住顺序不变式与 AC-10a argv 兼容红线；
  · 已实测把顺序换回去 → 2 条变红。
