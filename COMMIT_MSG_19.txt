fix(e2e): executor-python 在 Windows 上永远起不来——venv 相对路径在 cd 之后失效

e2e-full-windows 长期全红，每次真跑都失败（该 job 只在 PR 事件触发，历史上
只真跑过 2 次，两次都红——所以 push 轮全是 skipped、看不出来）。

失败现场：
    ✗ executor-python 在 60s 内未就绪: http://localhost:8003/health
    env: 'apps/executor-python/.venv/Scripts/python.exe': No such file or directory

根因不是「venv 没装」——CI 的 L-5 步骤确实建了 venv 并装了依赖（日志可见
Collecting fastapi…）。真正的原因：

  1. 探测分支在**脚本工作目录**下测出 PYTHON_BIN 是**相对路径**
     （apps/executor-python/.venv/Scripts/python.exe）；
  2. 启动段却 `( cd apps/executor-python && exec env ... "$PYTHON_BIN" )`——
     cd 之后那个相对路径立刻失效；
  3. env 于是报 No such file or directory，进程根本没起来，wait_http 空等
     60s 后才报「未就绪」，把人引向「服务起得慢」的错误方向。

对照 executor-node 分支从不踩这个坑：它用 `node dist/main.js`（命令名，与
cwd 无关），而 python 分支用的是路径。

修复：
- 探测后把 PYTHON_BIN 转成绝对路径再用（python3 是命令名，跳过转换）；
- 转换后加 `-x` 断言：真出问题时立刻报「解释器不可用」，而不是等 60s 超时
  后只报含糊的「未就绪」——本缺陷正是被这 60s 掩盖的。

验证（本机，Git Bash）：
  旧行为复现：相对路径 + cd → env: '...python.exe': No such file or directory
              （与 CI 报错逐字一致）
  新行为：    绝对路径 + cd → Python 3.12.13，且
              `import uvicorn, main` OK（uvicorn 0.48.0）——即 uvicorn 启动
              真正需要的前置条件成立，不止是 --version 能跑。

注：bash 的 pwd 产出 MSYS 形态（/d/a/...），Windows 原生 exe 靠 Git Bash 在
execve 前转 Win32；已实测 env 能正确执行。本机 Git Bash 的 pwd 不支持 -W
（非 MSYS2 bash），故不采用 pwd -W 方案。
