fix(ci): windows-node-tests 漏了 acf-cli 的 build，版本号守卫 MODULE_NOT_FOUND

CI 抓到（Windows 专属 job）：`windows-node-tests (packages/acf-cli)` 红，
`MODULE_NOT_FOUND: .../dist/index.js` + `requireStack: []`。

根因：`release-metadata.test.ts` 的版本号守卫会**执行构建产物**
（`node dist/index.js --version`）比对 package.json。而本包有**两个** CI job 跑测试
——`acf-cli-test` 与矩阵化的 `windows-node-tests`——我上一批只给前者加了 build
步骤，后者的 acf-cli 分支走的是 `npm run typecheck`，于是产物不存在、守卫报错。
**同一个包、同一个守卫，漏改一处就红一次**。

本机复现确认：清掉 dist 后 `node dist/index.js --version` 抛
`Cannot find module .../dist/index.js`（与 CI 逐字一致），证明是缺 build 而非
`require('../package.json')` 路径问题（后者在本机 Windows 上正常输出 1.4.3）。

修法两层（都不依赖对方）：
 ① `windows-node-tests` 的 acf-cli 分支补 `npm run build`（显式、失败信息清楚）；
 ② **把"确保产物在场"收进守卫自身**——产物缺失时就地 `npm run build` 后继续，
    而不是 `throw` 要求调用方先构建。理由：原先依赖的是"CI 里 build 排在 test
    之前"这一**约定**，而约定会漏（本次就漏了）；收进守卫后从**约定**变成
    **结构保证**，无论谁在什么顺序下跑、有几个 job 跑，它都自足。
    注意仍**不是**静默跳过：就地构建失败会抛出，断言照旧生效。

验证：acf-cli 112 passed / 1 skipped；实测删掉 dist 后守卫自愈（自动构建 → 8 条
全过，且 dist 被重建）；反证仍有效（把 `.version(pkg.version)` 改回硬编码
`'1.0.0'` → 2 条转红）；CI YAML 已解析确认两个 job 的步骤正确。
