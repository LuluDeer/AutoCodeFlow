fix(release): acf-cli 漏进 release-please manifest——Release PR 把它从 1.4.3 倒退到 1.0.0

解除 release-please 的永久卡点后（PR #4 标签 pending→tagged），release-please
首次真正开出了 Release PR（#9），立刻暴露出这个新缺陷：

    packages/acf-cli/package.json    - "version": "1.4.3"   + "version": "1.0.0"
    packages/mcp-server/package.json - "version": "1.4.3"   + "version": "1.5.0"

同批四个包，三个正常走 1.4.3 → 1.5.0，唯独 acf-cli 倒退到 1.0.0。

根因：release-please-manifest.json 是 release-please 的「上次发到哪了」基线。
acf-cli 在上一轮（b049272）写进了 release-please-config.json 的 packages 与
linked-versions.components，却漏进了 manifest——基线缺失时 release-please 把
它当全新包从 1.0.0 起算。

这是上一轮「acf-cli 漏进 linked-versions、卡在 1.0.0」（缺陷 #1）换了形态复发：
那次是永远不 bump，这次是版本倒退。两者都只在真正发版那天才暴露，且都会让
lockstep 破功、被 version-guard 在 tag 那一刻才拦下。

修复：
- release-please-manifest.json 补 packages/acf-cli: 1.4.3
- check-release-config.mjs 新增第 ⑤ 层：config.packages 与 manifest 的键必须
  一一对应（双向：漏条目 + 残留条目）。五层合起来保证「config 写了谁 /
  manifest 记了谁 / lockstep 带上谁 / version-guard 校验谁 / 矩阵发谁」
  五份事实指向同一个包集合。
- selftest 补 3 例（2 反例 + 1 向后兼容正向），总计 8 例 / 6 反例；
  收尾计数改为按 want>0 实算，不再写死「4 个反例」（已失真）。
- mutation 验证：移除 manifest 里的 acf-cli → 守卫精确报 ⑤ 并 exit 1。

PR #9 已作废关闭（它基于旧的、缺条目的 main 生成）。
