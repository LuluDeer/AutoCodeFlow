# 桌面客户端（executor-desktop）UI 全面审计与 v3 升级改造方案（2026-10-05）

> 审计对象：`apps/executor-desktop` 全部用户面 —— 主窗（状态监控 / 配置 / 历史 / 应用 四 Tab）、
> 首次运行向导（独立窗）、三个日志查看器（状态全屏 / 历史浮层 / 应用全屏）、系统托盘、系统通知、
> 更新横幅、ErrorBoundary 兜底页。
> 审计方法：渲染层全量源码精读（App/5 页/组件/2691 行 CSS/主进程窗口与托盘/通知/i18n）
> + 真实运行实拍 21 张截图（`e2e/screenshots.cjs` 写实夹具，含 800×720 窄窗通道）。
> 关系说明：本报告不重复 `docs/DESIGN-AUDIT-2026-09-22.md`（其主体是 admin-web）；
> 桌面端此前多轮小修（NETOPT / EXP / DEEP_REVIEW 系列）已解决的项不再列入。
> 本文是**升级方案**，不含代码改动；落地分期见 §5，风险与红线见 §6。

## 0. 总评与定位

桌面端当前是「明亮专业风」浅色体系，设计令牌（字阶/间距/圆角/阴影/动效曲线）、无障碍基础
（roving tabindex、焦点归还、reduced-motion 收口）、错误显性化（IPC 失败页内呈现）已经达到
相当好的水平——**这不是一个烂摊子，而是一个已到 75 分、继续小修无法到 90 分的系统**。
剩余差距集中在五件事上：

1. **视觉权威感不足**：标题规格四页四个样、宽屏空间大量空转、品牌字体缺位、状态色一词多色；
2. **日志（产品的核心对象）阅读体验未做「设计」**：三套查看器三种行为，元数据噪声占据 40% 行宽；
3. **信息架构按实现而非任务组织**：历史/应用是同一件事的两半、配置分区体量悬殊、状态页右栏低价值；
4. **引导缺口**：托盘常驻语义零说明、Agent 概念黑话、通知是死胡同、危险操作确认模式三套；
5. **动效只做了「入场」没做「因果」**：折叠无高度过渡、新日志无到达感、列表增量无过渡。

v3 方案的主线：**以「日志工作台」为产品主形象重构视觉与交互，用一套共享组件收口全部页面。**

### 1.6 已达标、明确不动的事项（防过度设计）

- 明亮风令牌体系（字阶/间距/圆角/阴影/双动效曲线）——保留，v3 只补缺令牌不推倒；

- 写实夹具回归基建（screenshots/ui-audit/full-layout-analysis 三脚本）——保留作为升级验收工具。

## 2. 新版设计方案（v3「日志工作台」）

### 2.1 设计原则（写进 CSS 头注释，作为后续 review 的裁判标准）

1. **一页一主对象**：状态页=日志流 + 今日健康度；历史=执行时间线；应用=版本资产；配置=表单。其余内容为辅助，让位。
2. **一种概念一个颜色**：运行中=蓝、成功/在线=绿、失败/断开=红、启动/等待=琥珀、停止/未启用=灰。全端唯一映射表（`STATUS_SEMANTICS` 常量 + CSS 令牌），徽章只准查表。
3. **宽屏不空转**：≥1500px 必须给出密度方案（多列/表格形态/侧栏），不允许「单列拉伸 + 大留白」。
4. **渐进披露**：默认路径只显示「能直接用的默认值」；原理、边界、错误代码全部收进「高级/详情」折叠。
5. **动效只表达因果**：入场一次、状态变化过渡、增量有到达感；不做装饰动画、不做循环发光（pulse 仅限「等待/进行中」一种语义、全端统一 1.2s）。

### 2.2 视觉体系收口（v3 tokens）

- **统一 PageHeader 组件**：`图标 20px + 标题 --fs-xl(20px)/700 + 副标题 12px text3 + 右侧 actions 区`。四页与向导标题全部换用；状态页 hero 收缩为 PageHeader 的「状态变体」（左舷状态条 + 图块 40px + 大字降为 `--fs-xl`，整卡高度从 ~96px 降到 ~64px，省出的空间给日志）。
- **字体升级**：内嵌 `Fira Sans`（Latin）woff2 + 可选 `Fira Code`，中文回落系统（Segoe UI/雅黑），等宽优先内嵌 `Cascadia Code`（Windows 10+ 自带，做探测回退即可）——CSP 已允许 self 字体；同时把 `--fs-xl` 用起来，删掉 18/19px 裸值。
- **状态色映射修复**：新增 `--blue` 徽章变体给「运行中」（历史 running 换蓝）；应用徽章去发光；「未启用」一律灰点灰徽章（修 A-05）。
- **焦点环**：实底深色钮采用「外环 accent + 2px 白色内衬」双层环；disabled 主按钮改 `灰底 + text3 字`，不用透明度。
- **MASTER.md 回写**：明亮风基线、绿色 DOC-01、字阶、组件清单同步进 `design-system/autocodeflow/MASTER.md`（或新建 `pages/executor-desktop.md` 覆盖文件，符合 MASTER 的 LOGIC 约定）。

### 2.3 日志阅读器 v3（本方案最大抓手：三合一）

抽公共组件 `components/LogViewer/`（数据源适配器注入），统一三处查看器，能力对齐到最高档：

- **布局**：一律 `position: fixed` 真全屏；顶栏=标题+元信息、搜索（Ctrl+F 全端生效）、级别 chips（全部/警告/错误 + 计数）、工具（折行/跟随/文件侧栏开关）；底部状态条（显示 x/y 行、缓冲上限提示）。
- **元数据降噪**：时间列固定宽右对齐（tabular-nums）；级别用 6px 色点+短文字（替代 44px 徽章块）；**traceId 连续相同时合并显示**——在该行块左侧以 2px 竖线 + 首行标注 `[trace 23fb6898]`，重复行不再渲染（修 A-03，心跳日志行宽立刻让给正文）。

## 5. 落地风险提示

1. **e2e/selftest 选择器连环依赖（最高概率风险）**：`screenshots.cjs / desktop-smoke / n10 / renderer.selftest.mjs` 大量 `getByRole/getByText` 依赖现有中文文案与 DOM 结构（如「查看日志」「卸载应用」「确定删除本地版本 v1.4.2」）。R1-R4 每一步都必须同步改断言并跑全量 `test:renderer + test:main + e2e`，否则绿色假象/红色误报交替出现。
2. **LogViewer 三合一是最高回归风险单点**：三套查看器各自携带日志规范化（双时间戳合并/级别判定/CRLF/增量游标/轮询与失败重试）的正确性投资（NETOPT-7⑥/EXP-09 等教训都在这里）。务必分两步：先抽组件原样迁移（行为不变、夹具回归通过），再做视觉/降噪改造；写实夹具（warn/error 混排、双时间戳、executor:err 通道）必须保留为固定回归用例。
3. **窗口底色强绑定**：任何画布色变化必须同步 `window-manager.ts` 两处 `backgroundColor: '#f5f6f8'`，否则复现 Windows frameless 闪色/割裂（WIN-DISPLAY 教训）。v3 建议把该色值提为共享常量并在 CI 断言。
4. **常驻挂载架构约束**：新组件不得引入「切 Tab 重挂载」；AppsPage 依赖 `MutationObserver(panel hidden)`，App.tsx 的 `TAB_SWITCH_EVENT` 白名单模式要保持；React.lazy 顶层创建约定（F-21）不得破坏。
5. **CSP/安全红线**：内嵌字体必须打进产物（self），禁止在线字体；新组件禁止内联 style 绕过 CSP 约定；`style-src 'unsafe-inline'` 现状不可再放宽。
6. **危险确认的摩擦权衡**：停止执行器加确认可能惹恼高频用户——按「仅存在 running 任务时确认」实现，且确认文案给「正在运行 N 个任务」的具体数字，不做常驻确认。
7. **双语过渡期观感**：i18n 只迁新组件会扩大「配置页双语、其余页中文」的剪刀差；二期迁移前，英文环境的整体体验反而可能比现在更碎——因此本期新组件文案双语化同时，至少把 Tab 标题/标题栏/向导三处「门面」文案一并入表（量小、暴露面最大）。
8. **MASTER.md 回写滞后风险**：若文档不同步，下轮贡献者会按深色 MASTER 造新页面——R1 必须包含文档回写，视为代码同级交付物。
