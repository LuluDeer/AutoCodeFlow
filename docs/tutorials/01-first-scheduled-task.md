# 教程 01 · 第一个定时任务

> 目标：从登录到看到第一个定时任务的执行结果，全程 ≤ 10 分钟。
> 前提：已用 `docker compose up -d` 启动全栈（见[快速上手](../quickstart.md)第一步）。

## 0. 三个核心概念

| 概念 | 是什么 | 在哪看 |
|------|--------|--------|
| **应用** | 任务的分组容器，按业务线/项目划分 | 左侧菜单「应用」 |
| **任务** | 一段会被调度的脚本 + 触发策略 + 重试/超时策略 | 左侧菜单「任务」 |
| **执行器** | 真正运行脚本的工作进程（node/python runtime） | 左侧菜单「执行器」 |

任务创建后由平台调度器按触发策略入队，空闲执行器领取并执行，日志实时回传，
结果落库为**执行记录**。

## 1. 登录

浏览器打开 **http://localhost**：

| 字段 | 值 |
|------|-----|
| 用户名 | `admin` |
| 密码 | `.env` 中 `INITIAL_ADMIN_PASSWORD` 的值（默认 `Admin@123456`） |

> 登录后先到「设置 → 个人信息」改密码。

## 2. 建应用

1. 左侧菜单 → **「应用」** → 右上角 **「新建应用」**
2. 名称填 `demo`，描述随意 → 「确认」

## 3. 建任务（两种方式）

### 方式 A：从模板一键创建（推荐，CORE-03）

平台内置 5 个官方任务模板（定时备份 / 健康巡检 / 数据同步 / 日志清理 /
Webhook 探活，与 MCP 侧模板同口径）：

1. 任务列表页点 **「模板」** 按钮（或左侧菜单进入「任务模板」页）
2. 选一个官方模板（如 `scheduled_backup`）→ **「使用此模板」**
3. 表单已预填模板 config，**只需补任务名称**（如 `my-first-cron`）、
   确认所属应用为 `demo` → 提交

### 方式 B：从空白表单创建

任务列表 → **「新建任务」**，关键字段：

| 字段 | 填什么 | 说明 |
|------|--------|------|
| 任务名称 | `my-first-cron` | 任意 |
| 所属应用 | `demo` | 刚创建的应用 |
| 调度方式 | `Cron` | 另有 fixed_rate / api / manual |
| Cron 表达式 | `*/5 * * * *` | 每 5 分钟；表单旁「Cron 助手」可视化选择 |
| 脚本类型 | `JavaScript` | 对应 node 执行器 |

脚本编辑器输入：

```javascript
const msg = `Hello from AutoCodeFlow! Time: ${new Date().toISOString()}`;
console.log(msg);
return { message: msg, success: true };
```

建议顺手配两条生产习惯用的策略字段（本教程可跳过）：

- `超时`：如 `60` 秒，超时后执行器杀进程树（`timeoutAction=kill` 缺省）；
- `runbook`（Markdown）：排障步骤，会展示在任务详情页并随失败通知/告警发出
  （FEAT-11）。

点 **「保存并启用」**。

## 4. 手动触发一次（不等调度）

1. 进入任务详情页 → 点 **「立即执行」**（`POST /api/tasks/:id/trigger`）
2. 切到 **「执行记录」** 标签页 → 点最新一条记录
3. 执行详情页看 **执行日志**（运行中实时推送）

预期结果：状态变绿色 `成功`，日志最后一行是
`Hello from AutoCodeFlow! Time: 2026-…`。

等满 5 分钟，执行记录里会出现第二条由 **cron 调度**触发的执行——至此
「定时」部分也验证完毕。

## 5. 看懂执行详情

| 区块 | 内容 |
|------|------|
| 状态/时长 | 成功、失败、超时（TIMEOUT）等终态与耗时 |
| 执行日志 | stdout/stderr 实时流；失败时含错误摘要 |
| 重试链路（CORE-02） | 配了 `maxRetry` 时显示 Attempt #N of M 与下次重试时刻 |
| traceId（OBS-01） | 跨端追踪 ID，开启 OTEL 后可到 Jaeger 查全链路 |

## 6. 失败了怎么办

> 想要一个现成的失败样本？`pnpm demo:failure:seed` 会预置一个故意失败的
> `demo-failure-fragile` 任务（含失败分类与错误详情），无需手工构造。

| 现象 | 排查 |
|------|------|
| 提示「无可用执行器」 | 「执行器」页看是否在线；注册后心跳同步约需 10-15 秒（见[快速上手常见问题](../quickstart.md#常见问题)） |
| 日志报模块找不到 | 说明脚本有依赖，请先读[教程 02 · 私服依赖](./02-private-registry-deps) |
| 一直显示「运行中」 | 检查是否配了 `timeout`；没配超时的任务会一直挂到执行器重启 |
