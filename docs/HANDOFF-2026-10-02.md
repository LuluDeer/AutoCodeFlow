## 二、N-14 落地：blockStrategy 闸门参数维度化（commit 0f231081）

chaos 复跑场景④的真发现：block 闸门此前只在 scheduler enqueue（cron/fixed_rate/
misfire）路径生效，手动/API/依赖触发经 `TaskService.trigger` 直入 BullMQ 完全
绕过。修复把闸门抽为共享 util（`task/block-strategy-gate.ts`），比较维度改为
**「任务+参数」**（params 规范化 JSON 等价：数组保序、键序无关）——同参才按
策略覆盖/丢弃，异参放行并发（参数化任务合法并发保住）。**朴素修复（直接套
手动路径）曾被否决**：会误伤"同任务不同参数"的合法并发。

验收：chaos 场景④复验 **FAIL→PASS**（同参覆盖+kill 下发、异参并发、discard
409 全命中，见 CHAOS-DRILL §9 场景④复验行）；闸门单测 18 例 + task.service
接线/扇出 5 例 + scheduler 回归 116/116；admin-api 全量 253 套件 4199 例绿；
trigger 端点补 409 文档，swagger/api-types 双产物同批。设计面五子问题（params
规范化规则、依赖链语义、opt-out 开关、中断不可续接边界、与互斥组正交）记录于
PLAN-CLAIMS N-14。

## 五、过程抓到的真缺陷清单（对账重点）

1. **metrics 认证·全局守卫先于控制器守卫**——/api/metrics 无 JWT 恒 401，共享
   令牌路径从未生效。修复：控制器 @Public() 跳过全局守卫（c900865e）。
2. **metrics 认证·JWT 回落裸奔风险**——跳过全局守卫后本守卫的 JWT 回落若复用
   基类会被 isPublic 短路（等于裸奔）。修复：NonPublicReflector 屏蔽 IS_PUBLIC，
   回落仍执行真实 JWT 校验（c900865e）。
3. **metrics 认证·配置路径错误**——守卫读顶层 `metricsScraperToken`，生产配置
   形状嵌在 `database.*` 节下（恒 undefined）。修复：database 路径 + 平铺兼容 +
   spec 生产形状回归（c900865e）。
4. **metrics DI·ConfigService 注入 undefined（根因 2026-10-02 收口）**——Nest
   `reflectConstructorParams` 合并 self-declared deps 时用**原型链敏感**的
   `Reflect.getMetadata`：基类 JwtAuthGuard 构造器 index[1] 的
   `@Inject(API_KEY_AUTH_FACADE)` 会覆写子类 MetricsScraperAuthGuard index[1]
   的 ConfigService 类型推断 → 按不存在的 token 解析失败 → `@Optional` 吞成
   undefined（strict-clone 探针实证：Nest 报 "argument API_KEY_AUTH_FACADE at
   index [1]"）。修复：守卫参数显式 `@Inject(ConfigService)` 覆盖回正确 token；
   DI 装配回归测试入 spec（真装配断言 + 上游行为锁定）；Nest 侧上游问题待报
   issue。process.env 兜底保留（服务无 ConfigModule 的极简装配）。
5. **chaos-drill.sh 两处脚本缺陷**——首行 UTF-8 BOM 炸 shebang；`redis-cli` 三
   处不带认证（requirepass 形态下场景 A 断言假阴性）。修复后 selftest 33/33
   （c900865e）。
6. **N-15 全局档自排除缺失**——dispatch 前本执行已被 claim 为 RUNNING（地址
   未落），全局占用计数把自己数进去 → max=1 时自己等自己。修复：计数排除自身
   行 + 单测对齐（38b32a0b）。
7. **compose 应用包链路断裂**——packageUrl 缺省拼内网 admin-api 地址，而 compose
   两个执行器服务段都没设 `EXECUTOR_ALLOW_PRIVATE_NETWORK`（默认 false）→ 执行
   器自己的 ssrf-guard 拒拉包，Docker 全家桶形态应用包任务必然失败（Windows 侧
   无 Docker 从未暴露）。修复：compose 显式放行（38b32a0b）。
8. **desktop-e2e maximize 假失败**——裸 Xvfb 无窗口管理器时 Electron
   maximize() 为 no-op，最大化用例确定性失败。修复：runner 装 openbox +
   显式 -screen 1280x1024x24（93fd42ff，入 main 33db92a7）。
9. **turbo 复测注记**（ARCH-28b 附录 A.6）——turbo 2.11.6 run 不接受
   `typecheck:*` 通配，须显式列任务；性能：冷 11.8s（−23.7%）/热缓存 1.25s
   （−91.9%），7/7 零失败。
