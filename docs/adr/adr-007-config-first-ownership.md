# ADR-007: 多来源配置优先级钉进契约

状态：Accepted（V1/webhook URL 优先级三轮两翻的教训）

## 背景

webhook URL 曾有三层来源（显式参数 / 已保存渠道 config / env），优先级在三轮演进中翻转两次，每次都有消费方被静默改道。"管理界面让用户以为生效的设置实际无效"（V1：PATCH config 后外发仍读 env）是配置面与生效面解耦的典型缺陷。

## 决策

1. 写路径与读路径共享同一事实源（ChannelConfigStore）；脱敏只作用于读面（GET 响应），绝不渗透发送路径；
2. 多来源优先级必须在端点文档明示 + **每层优先级各有独立测试**——翻转时旧断言被迫显式更新而非默默通过；
3. 掩码回写哨兵（S3）：GET 脱敏后的掩码值回写 PATCH 必须被识别为"未修改"，绝不能把掩码写回真实 env。

## 后果

- 配置类改动新增字段时，优先级矩阵测试是验收的一部分。
