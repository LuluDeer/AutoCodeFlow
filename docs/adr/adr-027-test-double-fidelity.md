# ADR-027: 测试替身必须保真——替身不保真 ⇒ 整类缺陷隐形

状态：Accepted

## 背景

2026-10-20 这一天的审计里，同一条教训在**三个独立场景**上重复出现：问题不是代码写错，而是
**测试替身（fake repository）的语义比真实依赖宽松**，于是某类缺陷在测试里根本不可见。

| 场景 | 替身当时的实现 | 隐形的缺陷 |
| --- | --- | --- |
| sop 状态机（R33-A2） | `update` 只比对 `id` | 「无条件覆写」与「带前置状态条件」在测试里**完全一样** ⇒ 一整族「读-改-写缺前置条件」缺口在 SOP 核心流程上长期存活 |
| sop 澄清并发（R34-A1） | 只处理了 `pulledAt: IsNull()`，其余 FindOperator 被忽略 | `Or(IsNull(), LessThan(...))`、`clarificationRound` 等条件写在测试里退化成无条件写 |
| users.update（R32-C3） | `save` 桩直接整对象覆盖 | 若不按 TypeORM 真实语义（重读行 → 逐列 diff → 只写差异列）实现，就**测不出**「陈旧快照回写」的行为，也做不出可信反证 |

共同点：**替身越宽松，生产代码的守卫越测不出来**。更危险的是它给出的是**假绿**——测试全绿、
覆盖率也涨了，而守卫在任何情况下都不会被执行到断言。这比没有测试更坏：它让人相信有保护。

## 决策

1. **替身必须实现被测代码实际依赖的语义**，而不是「能跑通」的最简实现。对 TypeORM 仓储至少包括：
   ① FindOperator 求值（`in` / `isNull` / `not` / `or` / `and` / `lessThan`…）；② **读返回快照副本**
   （不是行引用，否则调用方变量会被后续写入回灌）；③ `save` = 重读行 + 逐列 diff + 只写差异列；
   `update` = 列级写且**求值 where**。
2. **未知操作符必须抛错，不得静默忽略**。这是防假绿的最后一道：将来代码用了替身没实现的操作符时，
   测试要**炸**，而不是悄悄退化成「条件恒真」。
3. **测并发守卫时，替身必须能交错**：在 `update` 求值 `where` **之前**执行一次「并发写者」钩子，
   对齐真实 DB 的行锁顺序（别人的事务先提交，我们的条件 UPDATE 再对提交后的行求值）。没有这个钩子，
   「后到者不覆盖」这条断言就无从写起。
4. **替身保真度不足以回答问题时，升级到真实依赖做一次性探针**，而不是靠推测。先例：R32-C2 用
   **真 TypeORM + 真 PostgreSQL**（临时 schema，跑完 DROP）验证 `save` 是否回滚并发轮换——
   探针 A 证明不回滚、探针 B（改成 `addSelect` 装载该列）证明机理真实存在。
5. **反证必须能红**：把生产代码的守卫还原成缺陷版本，对应用例必须转红。若还原后仍绿，说明用例钉的
   不是守卫本身（此时先修用例，不要修生产代码）。

## 后果

- 正向：条件写、幂等短路、终态保护这类**不看代码就看不出**的守卫，第一次变得可断言；反证从
  「形式动作」变成真实信号（R33-A2 还原 4 处守卫 → 4 红 3 绿；R34-A1 还原 → 3 红 1 绿）。
- 代价：替身代码变长（FindOperator 求值 + 交错钩子），且**替身本身需要被测试**（本仓已有
  「fake 的 whereMatches 对 in / isNull 按真实语义求值」这类钉子用例）。这是必要开销：
  替身是测试的基础设施，它的正确性没有别的东西担保。
- 边界：不要求替身 100% 复刻数据库（事务隔离级别、锁等待、死锁检测都不模拟）。这些属于
  「实证不可替代」的部分 —— 由真机/真库探针与 compose 冒烟承担（见 ADR-008）。

## 替代方案（被否）

- **方案 A：单元测试一律连真实数据库**。否掉：单元层要的是秒级反馈；本仓 admin-api 单套件数量
  已上千，连库后每个用例付连接/清理成本，且引入 flakiness（并行、端口、容器）。真库只在
  「必须有实证」的少数问题上用（规则 4）。
- **方案 B：给每个仓库手写一个内存实现**（如 sql.js / pg-mem）。否掉：这类实现只覆盖 SQL 子集，
  **不支持 FindOperator 语义**正是本次缺陷的成因；且它们不模拟行锁顺序，等于把问题换个地方。
- **方案 C：不写替身，只在集成层测**。否掉：并发与竞态在集成层极难稳定复现（需要真实交错），
  反而会退化成「跑一百次碰运气」。
