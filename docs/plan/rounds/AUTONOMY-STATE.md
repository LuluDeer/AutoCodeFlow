## 教训（303–306）
- **303「守卫链绿 ≠ 产品测试绿」** —— `test:guards:repo` 是**零依赖守卫**、**不跑 web 测试**；代码**外提**会让「按文件路径读源码」的契约断言**静默失效**（断言还在、文件里已经没有那段文本）⇒ **只有跑全量才红**。纪律：外提后必须 grep「谁按这个路径读源码」；「按路径读源码」的断言 = **一份隐式依赖清单**，搬文件就同步登记表；**A 面绿推不出 B 面绿**。
- **304 替身必须兑现生产契约（ADR-027 的正例复现）** —— 裸 `vi.fn()` 返回 `undefined` 而生产返 **Promise** ⇒ 调用点 `.catch` 立刻抛错；**更糟的是被业务 catch 接住、弹假错误 toast** ⇒ 生成「产品看起来坏了」的假象并污染共享 DOM。纪律：**替身的返回值类型是契约的一部分**；假错误比没错误更难查；**共享状态被污染时先找「谁写了不该写的东西」**，不要先改断言。
- **305 测试里禁止「等固定毫秒数再断言」** —— `sleep(120)` 把「机器够快」当前提，全量并行 + 插桩时必破，且**单跑必绿**（所以长期被当成「不可复现」）。正确形态：`waitFor(该出现的东西)`（等**可观测事实**），再断言其余。纪律：**等事实不等时间**（时间只配上界 timeout）；「单跑绿、全量红」**优先怀疑时序假设**；修完要写清「为什么长期没被发现」。
- **306「修完 flake 才敢装门禁」** —— 把某端接入棘轮前必须先证明它**能稳定跑绿**，否则等于给门禁装一个**会自己红的判据**（人会怀疑判据，最后选择放宽 floor —— 而放宽是单向的）。纪律：接线前要有「**连续 exit 0**」的证据；已知抖动的端先「只收集不判定」——**先量化抖动，再定 floor 取法**；**门禁的每一次误红都在消耗它的权威**。
