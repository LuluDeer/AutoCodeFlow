## 教训（294–296）
- **294「有计数行但数字恒 0」比「没有计数行」更隐蔽** —— 前者能**骗过所有只看存在性的判据**：floor 0 对**任何**用例数都成立 ⇒ **看着有下界、其实没有下界**。① 判「这个指标有没有被守住」必须**同时核三件事**：「**计数行存在**」∧「**计数 > 0**」∧「**计数 ≥ 下界**」；② **下界必须来自实测**（floor 0 **不是保护**，它是「没有下界」的另一种写法）；③ 凡「计数/覆盖率/数量」类指标，都要问「**这个数字的口径是什么**」—— 口径写错时数字**稳定地、可解释地错**，而**稳定性恰恰是它骗人的地方**。
- **295「如实报 0」是对的，但 0 的含义必须有人核对** —— 数不出来就报 0（不编数字）是**正确设计**；错在**没人问过「为什么是 0」**（0 可能是「真的 0 条用例」，也可能是「口径选错了」）。① 新增 / 扩面登记的**第一条判据**应是「**这个 0 是真的 0，还是口径选错了**」—— 判法：**换成真实注册口径再跑一次，看数字是否变成非 0**；② 「数不出来就报 0」必须配一条「**0 是不合法**」的约束（否则它是最安全的假绿形态）；③ **口径要写在产生它的地方**（本轮写进登记表 `$comment`）。
- **296 批量扩面要保留「可验证的节奏」** —— 不一次扩 76 条：floor 必须来自**实测**且要**逐条**验证「**删了会红**」⇒ 批量登记会让「**登记了**」与「**真的被盯着**」再次脱钩（**这正是本判据要防的病**，批量登记等于批量制造它）。① 扩面批次要小到「**每条都能被单独验证**」；② **登记表里的一行在没有红演示之前只是声明**；③ **floor 只能来自实测**（凭空拍的 floor 会把「删光」和「正常增删」一起判红，或反过来**给 0 保护盖上「已保护」的章**）。
