## 教训（284–286）
- **284「方向相反的两个结论」不能共用一个空态文案** ——「没执行过」诱导**立刻手动触发**（= 多一次真实执行），「读不出来」应当**重试/报障** ⇒ 同一句话让人做**相反**的事。① 写空态前先问「它排除了哪一种原因」（真空/读失败/被截断），**排除不了就不许用空态**；② 错误态必须**整段替换**空态所在的位置；③ **同页既有的错误处置就是最强的口径基准** —— 同页口径不一致，错在「后果更重」的那处。
- **285 icon-only 控件的可访问名要说「马上要发生什么」，不是「它是什么」** —— 同一按钮两态**必须两个名字**；静态标签会让读屏用户听到的标签**与实际动作不符**。① 描述**动作与结果**，不是状态名词；② **名称随状态联动是判据的一部分**；③ 扫出「全仓唯一一处」时**先复核其余 N 处为什么合规**（`Form.Item` 的 `label[for]` **不等于**自带 `aria-label`）——那个**分母本身**要能被复核。
- **286「写不出测试」要区分「不值得测」与「测试工具链不够」** —— 本轮 F5 属**后者**：真渲染测不了 + 源码断言不被接受 ⇒ **正确解是先外提让它可测**，不是放弃判据或硬写源码断言。① 先分清「**断言对象不可达**」（改结构）与「**断言手段不对**」（换工具），**两种都不许降判据**；② **「零余量的文件」同时是最该外提的文件**（既挡改动又挡测试）；③ 源码文本锚的是「写下的字符」，**「有没有可访问名」最终必须落在 DOM 上**。
