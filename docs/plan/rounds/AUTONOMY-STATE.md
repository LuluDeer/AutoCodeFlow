## 方法论沉淀
- **「过期期望」是收紧类改动的系统性后遗症**，有三个亚型：①已红（体检能抓）②**仍在绿但测错东西**（假信心：mock 太早短路 / 只断言 scheme 级）③**死打桩**（打了已不再被调用的函数，删掉后仍绿）。②③比①危险，因为给假信心。
- **审计要能反证**：「删掉这段代码测试还绿吗？」是发现②③的最快手段。

## 纪律（并行版）
只信「命令 + 真实 exit code」；**先看 `signal` 再判退步**；**测试数据不可把「故意恒拒的目标」当合法样本**（用 TEST-NET 文档段）；**为过测试放宽安全不变量是最后手段且需 ADR**；**过期期望要改成正确断言，不是改成放行或 skip**；**审计要能反证「删掉这段还绿吗」**；**判据范围要够宽**；**全局豁免/自制 reporter 会让纪律形同虚设**；**测量实验要能作废自己**；**链必须在无在途改动时跑**；作者中断≠改动作废；一次只改一个文件 + `node --check`/`tsc` + 失败即回滚；定位代码块只用 CodeGraph；断言源码文本必须登记；`git add` 显式路径；遇 `index.lock` sleep 2s 重试；**禁 `pkill -f`**。
