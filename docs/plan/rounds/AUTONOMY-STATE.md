## ⚠ 今天最重要的发现（设计级，W3 真 PG 实证）
**广播扇出占坑与心跳下限在同一列上语义相反**：
- `executor.service.ts:6034` 广播对**每个**接单执行器 `+1`，但 `:5852-5855` 既有注释写明「单执行行的占用标记 `executorAddress` 只能落一个地址」⇒ 未持有执行行的广播目标 **`counter=1 / rows=0`**（真 PG：`e2: counter=1/rows=0`）；
- **R108/ADR-037 的心跳下限按行数取大** ⇒ 心跳**看不见**广播占坑；而 `:6022-6025` 的既有注释**依赖**「广播少计由执行器心跳 30s 覆写兜底」 ⇒ 与「心跳不得改小」**方向相反**，在广播目标上**互相抵消** ⇒ **容量少计 ⇒ 可被多派单播任务**。
- **已按闸门立项**：派 W3 写 **ADR-038**（方案 A 给广播目标也落行 / **B 拆独立列 `broadcastReservedCount`（我倾向）** / C 记为已知限制；含影响面、迁移守规、无开关理由、分步红→绿）。**零实现改动**。

## 不变量取证的另外两条（`artifacts/autonomy/R119-api/count-le-rows.sh`）
- **A 段（单播 + 生产语义：容量不足保留行）** ⇒ 10 轮 `counter=4/rows=4`，**0/10 破裂** ⇒ **生产对单播恒成立**；
- **B 段（反向对照：占坑后删行）** ⇒ `counter=1/rows=1` → **`counter=1/rows=0` 破裂** ⇒ **只有删行才破不变量**；
- ⇒ 结论：**W1 的断言 `finalCount <= inFlight` 必须限定「单播」**（广播形状会周期性假红，而那是设计问题不是 harness bug）；单播下那 1 轮 `finalCount > inFlight` 最可能仍是**失败路径删行**的记账假象。

## 方法学（累积，本轮新增标 ★）
只信「命令 + 真实 exit code」；**同一列上两种相反语义会互相抵消**（★R108「心跳不得改小」 vs 广播「靠心跳覆写兜底」）——发现这类冲突要**先立 ADR 再动代码**；**不变量有适用范围**（★`计数 ≤ 行数` 只对单播成立，广播扇出天然破裂）；**没有 dump 不归因产品**；**测量工具会撒谎**；**比对方向错会造假违反**；**harness 缺陷与产品缺陷必须分栏**；**不变量要写成断言**；**记账口径要与生产一致**；不编造 sha；文档与实测要对账；验收用链内同形式；收紧判据后要复验原反例仍被抓；守卫防「先咬自己」；前缀式清理/固定临时路径是并行互杀源；样本量不足的绿不算绿；「期望值同源」≠ oracle 成立；修前先证窗口可达；假 oracle 要删；抖动段不挂门禁；基线撞上限不许调上限；强/弱反向验证分开记；先看 `signal` 再判退步；一次只改一个文件；定位代码块只用 CodeGraph；断言源码文本必须登记；`git add` 显式路径；遇 `index.lock` sleep 2s 重试；**禁 `pkill -f`**。
