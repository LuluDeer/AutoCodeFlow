## 教训（442–443，接 441）
- **442「CI 环境比用户环境更『宽容』时，缺陷只在用户那边出现」** —— GitHub `ubuntu-latest` 自带 `python` 别名 ⇒ 7 个脚本在 CI 永远绿、在较新真实发行版上全不可用。不是 CI 配错，而是**CI 的隐式便利掩盖了脚本对环境的假设**。⇒ 凡脚本出现**未加版本号的解释器名**，就问「这个别名在我支持的所有发行版上都存在吗」。
- **443「换解释器之前先问『依赖在哪』」** —— 看到 `python: not found` 的直觉是换 `python3`，但那只是把「命令找不到」换成「51 个 collection error」：**症状变了，根因没动**。本仓 Python 依赖在**项目 venv** 里 ⇒ 正确修法是**探测 venv**。
