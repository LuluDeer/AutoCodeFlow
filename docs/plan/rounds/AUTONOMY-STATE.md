## 教训（288–290）
- **288「回落口径」不是保守，是洞** —— 回落源能被**另一条命令前移**（`--skip-heavy` 前移 `generatedAt`）时，「缺失就回落」= 一条**看起来新鲜**的假绿通道。**收紧不是删回落，而是不许两种口径混用**：声明了细粒度承诺（`maxAgeHours`）就必须有细粒度证据（per-step `measuredAt`），缺失即红、不回落；未声明的端保留回落但**显式登记为已知盲区**。① 判「保守」前先问**回落源会不会被别的路径改写**；② **「缺证据」与「证据过期」是两条红**，报文必须分得开（否则把「没人测」误读成「测过但旧」）；③ **把口径写进契约**（`measuredAtPolicy` + 刷新命令）。
- **289 固定临时路径 = 并行互杀源（第三次复现）** —— 同一脚本 python 臂早已 `mkdtempSync`、admin / node 漏网 ⇒ 并发/被杀进程互踩、**随机 ENOENT**、「重跑就好」。① **修反模式要扫同一文件的所有同类臂**，不只修报错那一处；② **「随机红 + 重跑就好」优先怀疑共享可变路径**，不要先归为 flake；③ **判据面就是并发** ⇒ 验证要写「N 并发全绿 + 零残留」，不是「跑一遍绿」。
- **290 并发丢数据要「重测」不要「手写」** —— 本轮并发 read-modify-write **丢掉 node 的 `measuredAt`**，正确补法是**真跑一次（19s）**；手填的时间戳与真跑**格式完全一样**，判据永远发现不了。① 证据字段（`measuredAt` / hash / sha）丢失后**一律重跑**；② 并发写同一文件**按根因裁决**（→ 244）：Lead 裁决「停手 + 只交验证报告」、单一写者统一提交；③ **台账要记证据的来路**（真跑 / 复用 / 手写）—— 同值不同来路，可信度完全不同。
