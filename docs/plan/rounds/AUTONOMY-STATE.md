## 教训（270–273）
- **270「永远红的守卫等于没有守卫」**：判据面必须**按族的语义**限定（后端 431 码 vs MCP 表 3 条 ⇒ 只核 `TASK_FIRE_POINT_*` 族），否则第一天就红 **428** 条且永远红 ⇒ 守卫被加豁免 ⇒ **豁免是全局的，真漂移也一起被豁免掉**。限定要写进**判据名与报文**，并用**控制组用例**钉住（族外的码不在表里 ⇒ 必须 exit 0）；「这个守卫会不会一直红」要作为守卫的**验收项**（常年红的守卫不是防线，是噪音源）；
- **271 第二份事实源必须配一条漂移闸**：「结构上不可复用 ⇒ 只能写第二份」成立时，第二份的**存在本身就要附带一条守卫**；头注写「两边都要看」只是**提醒**（记忆没有 exit code），**机制是守卫 + 结构红**。判据三段式：第二份每个键在真值源存在 + **被承诺同步的那一族**每个键在第二份存在（这条才是漂移的真实形态）+ 同名字段取值一致。**做不到全量同步 ≠ 不做守卫 —— 能做的那一族先做**；
- **272 判据面塌方要结构红，不许退化成「0 项合规」**：任何「A ⊆ B」型守卫在解析面失效时都得到**空集合**，而空集合恒满足包含关系 ⇒ **永远绿**。必须为「读不出」与「读到但确实为空」准备**分离**的出口（解析失败 / 文件缺失 / 字面量不闭合 / 出现本守卫读不到的键形状 / 解析出 0 条 / 家族前缀被改名致 0 个码 ⇒ 六种一律 exit 1 点名结构红，报文要说「扫描器失效」，不许说「0 项漂移」）。与 R143 的「扫描面下界（`MIN_*` 锁分母）」同族，区别是这里锁的是**分子的可解析性**；
- **273「现况数字」要带日期与 HEAD，并写明覆盖面边界**：三件套 = **数字 + 测它的时刻与 HEAD + 它相对上一版变了什么**；只写「大部分/多数」信息量为零且同样会漂移；写了新数却不写「上一版是 2026-10-30 快照」会被读成「同一天两个数打架」。另：**数字要连口径一起写**（91 个守卫 ≠ 91 个受覆盖计数保护，实际只有 13 个）—— **写具体数若不写清口径，就会变成新谎言**。
