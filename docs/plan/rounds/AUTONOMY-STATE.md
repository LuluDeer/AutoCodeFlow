## 教训（469–470，接 468）
- **469「『不接』必须有**写在该文件自己头注里**的理由，而不是评审时的记忆」** —— 后 3 个能干净判「不接」，是因为头注**自己写着** needs-env/分钟级/需 docker。若理由只存在于某轮对话，下一个人会**重新判一遍**、很可能判成「忘了接」而顺手接上 ⇒ 门禁变慢或变红。⇒ **「为什么不做」要和「做了什么」一样留痕**，且留在**被执行的对象旁边**。
- **470「审计的结果应当是一张**带处置**的表，而不是一串名字」** —— 若只报「这 7 个没人跑」，下次会重复审计；拆成「4 接 / 3 不接 + 各自理由」之后，**这次审计就是终态**。⇒ 「N 个有问题」的产出价值 ≈ 0；**「N 个各归何处」才是可复用的结论**。
