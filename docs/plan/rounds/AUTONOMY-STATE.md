## 教训（262–265）
- **262「假红」要先分清是判据错还是采集面错**：i18n 那 6 处**判据没写错**，错的是**采集面把测试基础设施算进了判据面**。**改判据**会让真问题漏网；**登记豁免**是「登记代替修复」（判据面随新增诊断串膨胀，最后没人读得懂「已接受 N 处」）⇒ 判据：**报红时先问「这条串/这个文件在不在判据的语义面里」**，不在 ⇒ **修采集面**（显式清单 + 钉边界的用例）；
- **263 守卫缺 selftest = 判据面本身没人守护**：本仓多数守卫有 `--selftest`，`i18n-scan` 没有 ⇒ 采集面一放宽**不会有任何东西变红**。**补 selftest 与补判据同等重要**（它最容易在「修一次假红」的改动里被顺手改宽）；附带反面：**补了 selftest 还要接线**（否则只是从「没有自检」变成「有自检但没人跑」—— 见候选池第 1 条）；
- **264「日期/时间」类字段要区分「文件级」与「测量级」**：文件级 `generatedAt` 前移**不等于数据新**（它答「文件哪天生成」，不答「这步何时真测过」）⇒ 两条写入路径共用一份文件时，「文件日期」被当成「数据年龄」，一侧假绿、一侧假红。判据：**加「测量级」字段**，**沿用不是重测 ⇒ 时间戳不许刷新**（靠复用 `prev` 原对象做结构保证），回落规则写死「优先测量级 → 回落文件级 → 都缺即红」并**点名来源**；
- **265 两个上限并存时取更严者，别定「谁优先」**：`min(days×24, hours)`。只认一个 ⇒ 旧字段变装饰；定优先级 ⇒ **暗规则**（读者判断不出生效的是哪个，且方向明天可能被误改）；`min` **让收紧永远单向**（棘轮友好），两者等价时可回归验证（`age×24 > days×24` ⟺ `age > days` ⇒ 既有语义一位没变）。⇒ 凡「新旧两套口径并存」，都写「取更严者」+ 换算等价性证明，**不写「以 X 为准」**。
