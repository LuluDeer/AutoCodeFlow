## 本轮落地：ADR-038 定稿（`7c751ca7`，W3，零实现改动）
**问题**：广播扇出占坑与心跳下限**在同一列上语义相反**（`executor.service.ts:6034` 每台 +1 vs `:5852-5855` 占用标记只落一个地址 ⇒ 未持行目标 `counter=1/rows=0`；而 `:6022-6025` 的既有注释**依赖**「广播少计靠心跳 30s 覆写兜底」，与 R108「心跳不得改小」方向相反）。

**四案对比（ADR 结论）**：
- **A** 广播目标也落占用行 ⇒ `task_executions` **行语义崩塌**（统计/回填/回调/用户可见"执行数"全变）；
- **B（推荐）** 独立列 `broadcastReservedCount`：容量 = **两列之和**，心跳下限**只管单播行数** ⇒ **零用户可见变化**（`admin-web/src/utils/executor-metrics.ts:6` 的"实际在跑"口径原样）、与 ADR-037 **正交**；
- **C** 记为已知限制 ⇒ 最省事最危险，等于**把超卖写成已声明行为**（ADR-029 已否此路线）；
- **D** 独立占用表+TTL ⇒ B 的超集代价（热路径多 join + 清理任务）。

**迁移**：可空+默认 0 在线加列，`down()`=`DROP COLUMN`，须过 `check:migrations` / `check:migration-symmetry`；**回滚无需数据修补**（新列最坏从 0 累计 = 短时少派单、**不超卖**）；**不设开关**（三次裁决）。
**失效半径方向性（写进 ADR）**：新列**漏释放** ⇒ 少派单（安全方向）；真正危险是**漏把它算进容量谓词** ⇒ 超卖方向 ⇒ 实现轮按此排优先级。
**步骤 1 自带否决条件**：若「广播到 N 台后每台容量占用 ≥ 1」在当前 HEAD 是**绿**的 ⇒ 说明 R119 C 段在集成层不成立，**停手重查**，不许拿测不出问题的判据驱动实现。
