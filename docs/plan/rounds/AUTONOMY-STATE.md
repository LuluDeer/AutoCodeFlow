## 教训（463–464，接 462）
- **463「可选参数的注释若写『仅测试用』，就必须数一遍真实调用点；0 ⇒ 它是噪音不是接口」** —— `lockKey` 挂在那里让读者以为「测试注入不同 key 是既有做法」，而实际做法恰恰相反（spec 断言**同一个**常量）。**注释在说一件事，代码在做另一件事**。⇒ 这类缝价值是负的：它**暗示了一种本项目刻意禁止的用法**。
- **464「删掉未使用的注入点时，原位要留『为什么删』而不是留空白」** —— 留空白的后果：下一个人看到选项**不存在**，可能**重新加一个**（他真的需要隔离时）。⇒ **删除也是设计决定，需要留下痕迹**，否则同一件事会被反复重新引入。
