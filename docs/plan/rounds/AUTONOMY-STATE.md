**基线**：以 `git log -1` 为准 · **5 worker 并行** · **守卫链 98 段全绿**（含可见豁免）
**会话**：第 108 轮 · 并行第 41 批

## R18-B 的真相（两轮读码证伪后收敛，**这是本轮最有价值的结论**）
- **方案 B（下限改读占坑数）**：否 —— 心跳 `GREATEST` 后**永远无法降计数** ⇒ 重启若计数陈旧偏高 ⇒ **永久饥饿 I2**；
- **方案 C（claim 与建行同事务）**：**前提被证伪** —— 执行行在**入队之前**就已创建（`scheduler.service.ts:2855` save → `:2895` enqueue → `task.processor.ts:326` dispatch 传现成行 → `executor.service.ts:4890` 签名即接收），占坑只改计数（`executor-dispatch-slot.collaborator.ts:146`）⇒「**占坑已成 / 行未建**」在生产**不可达**；C 在修不存在的窗口（9 处直调点全在 `executor.mutex-claim.spec.ts`，是测试而非生产调用）；
- **真实缺陷 = 心跳自身的 TOCTOU**：`executor.service.ts:3807` 的 `count` → `:3840` 的 `repo.update` 两步之间，并发派发加的占坑被过期 count 覆盖 ⇒ 超卖；
- **修法 = 一条原子 UPDATE**：`SET runningTaskCount = GREATEST($上报, (SELECT count(*) … 非终态))` —— 原子、省一次往返、**无事务、无迁移、无开关**；且子查询是**实时**的 ⇒ 不会饥饿（这正是它优于 B 的地方）。

**ADR-037 已定稿**（`8059aa9c`，按「否掉 B/C/D/E + 采纳单语句收敛」写）：9 处直调点列全、影响面/回滚（单 commit revert、无迁移、不设开关，引 ADR-032/033/035 三次裁决「双轨＝制度化两种承诺」）、4 步计划（步骤 1 = 让验收可测）。**踩坑记录**：`test:docs` 抓到 4 条死链——ADR-016/030 的文件名凭印象写错，已改正。

## 纪律（并行版）
只信「命令 + 真实 exit code」；**能被反例证伪的判断优先于「保持一致」**（W3 两轮推翻自己，两次都给读码证据，这比坚持更值钱）；**修之前先证「这个窗口真的可达」**（否则会在不存在的缺陷上做结构性重构）；**oracle 必须随产品变化**（纯模拟的 `--fixed` 是假 oracle，已要求删除）；**模式名要诚实**（不叫 `--window` 叫 `--toctou`）；**恒红段用可见豁免**（带到期日+每轮打印），不用关灯键；**结构性重构先 ADR**；基线撞上限不许调上限；未超阈值文件不登记；强/弱反向验证分开记；先看 `signal` 再判退步；链在无在途改动时跑；一次只改一个文件；定位代码块只用 CodeGraph；断言源码文本必须登记；`git add` 显式路径；遇 `index.lock` sleep 2s 重试；**禁 `pkill -f`**。
