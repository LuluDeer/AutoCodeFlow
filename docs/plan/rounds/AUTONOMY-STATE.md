## 教训（297–299）
- **297「floor 0 不是保护」** —— 计数只有 1 条用例时，下界**只能是 0**（0 ≤ 任何数恒真）⇒ **登记它等于登记装饰**；正确顺序是**先补用例、再登记**，**不能反着来**：登记了却没下界**比不登记更危险** —— 不登记时没人以为它受保护，登记了会**让人以为受保护了**（用登记的形态冒充保护，→ 296）。① **登记前先问「这个 floor 相对实测用例数够不够紧」**（最低标准：删掉一半会红）；② **floor 与用例数要一起看** —— 单看 `floor=2` 像保护，看到「用例 4 条」才知道它只挡「删到 2 条以下」；③ **先补用例再登记是顺序问题、不是工作量问题** —— 反过来做的中间态是**「挂着『已保护』章的裸奔」，且没有任何判据能发现它**。
- **298「读不到 ⇒ 当成 0 项通过」是判据面塌方的通用形态** —— 本轮三条新自检**钉的都是这一族**：读不到契约 ⇒ 0 项 · 缺实现 ⇒ 0 差异 · 一个脚本都跑不了 ⇒ 0 未覆盖。**形态不同、病理同一：把「输入缺失」复述成「检查通过」** ⇒ 判据的输出**恰恰与事实相反**（塌方看起来最干净）。① **任何判据的第一条用例都该是「输入缺失时必须红」**（收益高于任何正例）；② 写判据时**先列出它依赖的每种输入**，逐个问「读不到时我报什么」—— 答「0 项 / 0 问题 / 通过」的**全是要修的点**；③ **「空」与「关掉」必须可区分** —— 置空要**回落默认清单**，否则**清空配置就是最方便的关闸方式**（→ 275 的镜像：**静默空回落 = 最方便的假绿**）。
- **299「自检」要接进两面才算数** —— **加了 `--selftest` 不等于自检会被执行**：本轮 `check-guard-liveness` 就是这样 —— 脚本里有自检，但 `package.json` **只有主跑入口**、CI 也没跑 `--selftest` ⇒ **自检从未执行过一次**，而它**看起来是齐的**。接线三处（**npm script 合并 / CI step 改走 script / 计数口径换真实注册方式**）**缺一不可**。① **判「自检存在」要判「自检被执行」** —— 文件里有 `--selftest` 分支是**声明**，两面核对才是**证据**（→ 266 的强化：连入口都没有时，连「跑没跑到」都无从谈起）；② **同一件事的多个接点要一次改完** —— 分两次改的中间态是**「自检写了但从不跑」**，而它**看起来完全正常**；③ 给「接好了」**配一条会叫的判据**（两面核对 + 覆盖计数），否则下一次「只接一面」照样能过关。
