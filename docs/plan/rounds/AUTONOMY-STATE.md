## ✅ R18-B 定性完成（ADR-037 §5b，`121a7f77`）
- **机制真实**：「未提交行对子查询不可见」**存在**（模型 A：`BEGIN; +1 占坑; INSERT 行; sleep 1; COMMIT` + 心跳在窗口内 UPDATE ⇒ 子查询看不见、EPQ 仍用语句快照 ⇒ 写回 0 抹掉已提交的 +1 ⇒ **final=0/rows=1 超卖**，**3/3 确定性**）；
- **但生产属模型 B**：`scheduler.service.ts:2855` 建行并提交 → `:2895` 入队 → `dispatch:4890` → 占坑 `executor-dispatch-slot.collaborator.ts:146` ⇒ 心跳语句开始时行**必然已提交** ⇒ **模型 B 3/3 安全、产品无残窗**；
- **⇒ 不需要加锁**（加 `FOR UPDATE` 只是为不可达路径付延迟）；**且若真按原方案 C 把占坑与建行合并进同一事务，反而会「打开」这个窗口** —— 这是**否掉 C 的第二条理由**（第一条是窗口不可达）。
- **R108 的修复仍然是对的**：R108 真 PG 时序证据是**应用层两步（count→update）用过期快照覆盖**（t0=3、真实在途=5、旧实现写 3）⇒ 原子 `GREATEST` 闭合的是那个真缺陷。

## ⚠ 1/20 违反 = 环境互杀（不是产品问题）
`scripts/heartbeat-dispatch-race-selftest.mjs:195` 启动时按**前缀** `docker rm -f acf-r16-*` ⇒ **杀掉并发实例的活容器**（W3 `ps` 抓到另一 worker 同一 harness 正在跑；同期出现 `exit 137` / `No such container`）。**隔离后 20/20 与 50/50 都是 0 违反**。
**⇒ 教训**：多 agent 并行下，**前缀式清理（`docker rm -f <prefix>*`）是跨会话互杀源**；已要求改为「只清自己 + 检测到同前缀并发 ⇒ exit 2 并点名」，并建议立一条守卫扫这类通配/前缀清理。

## 纪律（并行版）
只信「命令 + 真实 exit code」；**样本量不足的绿不算绿**；**「期望值同源」≠ oracle 成立（写入路径也要同源）**；**同源签名 = 反向验证同时击穿判据层与产品层**；**原子化 ≠ 闭合，还要问「子查询看不见谁」**；**先分清「模型不可达」与「产品残窗」再决定加锁**；**多 agent 并行下前缀式清理=互杀**；**诊断代码要自检「失败也不静默」**；假 oracle 要删；抖动段不挂门禁；基线撞上限不许调上限；强/弱反向验证分开记；先看 `signal` 再判退步；链在无在途改动时跑；一次只改一个文件；定位代码块只用 CodeGraph；断言源码文本必须登记；`git add` 显式路径；遇 `index.lock` sleep 2s 重试；**禁 `pkill -f`**。
