## 详细复核

### A. 上一轮修复面

- 共享凭据出口（`executor.sharedToken`、`getExecutorSharedToken`）：待补证。应逐一核对配置读取、请求鉴权、中间层权限映射和包下载分支，不能仅因存在共享 token 即判定越权。
- 包下载双通道：待补证。应核对路由注册顺序、静态资源前缀和参数化路径，确认共享 token 仅可访问包下载资源而不能匹配其他管理员资源。
- executor-node 停机：待补证。应核对 `server.close`、10 秒 drain、执行记录落盘及 `main.ts` 全部 signal/异常出口，重点确认重复信号和 close 回调不会丢失状态。
- 前端认证状态机：待补证。应沿 401→refresh→重放、退出撤销、失败重试和状态回写路径检查请求去重及循环终止条件。

### B. 低覆盖模块专项

本轮未把“未找到调用”作为缺陷，也未对凭据存储、IPC 路径参数、子进程环境继承、SDK 禁用/降级语义作无证据断言。以下均为待补证检查项：

1. `apps/executor-desktop`：凭据存储边界、IPC 参数校验、子进程环境变量继承。
2. `packages/acf-cli`：认证传递、禁用/降级行为及重试出口。
3. `packages/mcp-server`：工具调用到 API 鉴权的完整链路。
4. `packages/autocodeflow-node-sdk`、`packages/autoflow-sdk`：认证传递、禁用/降级语义、重试上限与错误传播。
5. `apps/registry-npm`：下载路由与 token 权限边界。
