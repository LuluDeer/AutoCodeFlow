## 填写要点（读完再动笔）

- **锚点必须真实**：`file:line` 打开核对过再写；不确定就只写 file（atlas 维护规则第 3 条：禁止编造，核实不了标 `> ⚠️ 待核实`）。
- **命令必须可复制执行**：写进"复现步骤"的命令先在本机跑通。
- **验证数字要具体**：`"测试通过"` 不合格，`"npm run test:nginx-sse 19/19 通过"` 合格。
- **预防段落回链 atlas**：若该问题修正了某个模块文档的认知，给出相对链接（如 `../../01-apps/admin-api/modules/task.md`），并刷新那篇的"最后核对"日期。
- **状态三选一，不写第四种**：`未定`（还在查）/`已解决`（有验证证据）/`规避`（决定不修，写明依据——ADR 编号或板上拍板记录）。修复任务的认领状态仍以 `docs/PLAN-CLAIMS.md` 为准，两者不要互相替代。
- **一份记录只讲一个根因**：排查中发现的其他独立问题各自开新文件，在"相关代码锚点"或"预防"里互相引用即可。
