# VERIFY：gui-x11 S2 真机验收（Linux GUI 能力，2026-09-27）

> 范围：executor-desktop Agent GUI 能力域 Linux 后端（`gui-x11.ts`，S1 于 7ce160d5 落地）。
> 环境：Linux 开发机（Ubuntu 24.04，GNOME **Wayland** 会话 + XWayland；xdotool 3.20160805.1，
> ImageMagick 6.9 q16，ffmpeg 4.4+，Xvfb + zenity 构成正向验证栈）。
> 结论：**S2 通过**——正向全链 7/7（Xvfb 合成 WM 栈）+ 负向如实拒绝（GNOME Wayland 实机）+
> desktop 自检链 35 套全绿。五处工具链现实在验收中被挖出并全部以驱动层加固收口。

## 1. 负向验证（GNOME Wayland 实机，`scripts/gui-x11-s2-verify.mjs`）

目标：证明「安全不变量无法成立的环境」下能力被**如实拒绝**，绝不盲注入。

| 用例 | 结果 |
| --- | --- |
| probe（DISPLAY=:0，xdotool/import 在场，几何可读） | ✅ **false**——EWMH `_NET_ACTIVE_WINDOW` 恒空（xprop 实测 `0x0`），前台身份验证无基座 |
| focus(shadowbot) / screenshot / click | ✅ 全部 `x11_gui_unavailable` 拒绝（能力未声明） |
| Wayland 原生窗口（gnome-shell 类）不可达 | ✅ `app_main_window_not_found` |
| 未知应用拒绝 | ✅ `app_main_window_not_found` |

要点：影刀（ShadowBot）的 WM_CLASS 实测为 `ShadowBot`（首字母大写）且其主 IDE 疑似
Wayland 原生——XWayland 侧仅见 ≤364×140 的辅助窗。**GNOME Wayland 会话上的 gui
能力被 probe 如意 withhold**（矩阵纪律：宁可如实不支持，不做假闸门）；运维文档已
注明改用 Xorg/X11 会话登录即可完整启用。

## 2. 正向验证（Xvfb 合成 WM 栈，`scripts/gui-x11-s2-xvfb-verify.mjs`）

Xvfb（真 X 服务器，无 Wayland 限制：XGetImage/XTEST 全可用）+ zenity（GTK，自设
`_NET_WM_PID` 供属主核对）+ xprop 手动维护 `_NET_ACTIVE_WINDOW`/`_NET_SUPPORTED`
模拟 WM 职责。**诚实边界**：合成 WM 验证的是驱动逻辑端到端 + 物理注入，非真实 WM
生态（后者属滚动项，见 §5）。

| # | 用例 | 结果 |
| --- | --- | --- |
| 1 | probe（几何 + EWMH 基座就位） | ✅ |
| 2 | focus(zenity)——枚举→pid/comm 属主核对→activate→轮询验证 | ✅ focused |
| 3 | screenshot 窗口级（ffmpeg x11grab 区域抓取） | ✅ 139KB PNG |
| 4 | click OK 按钮 → **对话框被物理关闭** | ✅ 注入物理生效 |
| 5 | press ENTER → **第二个对话框被物理关闭** | ✅ 键盘注入物理生效 |
| 6 | type（XTEST + 逐块前台复核） | ✅ |
| 7 | 拒绝：越界点击 | ✅ `click_outside_window` |

**7/7 通过**（脚本退出码 0）。

## 3. 验收挖出的五处工具链现实（全部已加固 + selftest 钉住）

| # | 现实（实测） | 驱动加固 |
| --- | --- | --- |
| F1 | GNOME Wayland 的 XWayland 不维护 `_NET_ACTIVE_WINDOW`（恒 `0x0`）；`import` 的 XGetImage 在真桌面与 Xvfb 同报 EAGAIN | probe 增加第三道硬条件：`getactivewindow` 必须可读——无验证基座的环境能力整体 withhold |
| F2 | xdotool `--class` 是 POSIX ERE：不接受 `(?:...)`（exit 13），且 WM_CLASS 常带大写（`ShadowBot`） | 锚定模式 `^…$` + 逐字母大小写折叠 `[xX]`；属主 comm 比较对齐 Windows 驱动的大小写不敏感语义 |
| F3 | xdotool search 无匹配 = exit 1 + 空输出；`--onlyvisible` 在 GNOME Wayland 下不可靠（带过滤全空、窗口真实在屏） | 空匹配按空集处理（编译失败仍上抛）；移除 `--onlyvisible`，可见性交给 activate + 前台复核兜底 |
| F4 | xdotool 3.2016 无 `getwindowpid --shell`（裸数字 / "has pid N" / "no pid" 散文三态） | `parsePid` 严格形态解析——失败文案里的窗口 id 绝不被误当 pid |
| F5 | ImageMagick import/convert 的 XGetImage 在本机栈全灭（EAGAIN）；xwd BadMatch；**ffmpeg x11grab 是唯一可用捕获路径** | 截图后端 = ffmpeg 区域抓取（等价窗口矩形；遮挡含入——与点击命中弱化同族，已登记），import 保留为其他栈后备 |

同批修正的两处语义：`windowactivate` 不用 `--sync`（无 WM 环境会永久等待）改为有界
轮询验证；事后校验容忍「目标被动作自身关闭」（点击/按键命中最小化按钮后活动窗口无
从读起——目标不存在即不存在被劫持面，如实标注 `target closed by action`）。
