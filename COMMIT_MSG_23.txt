docs(release): 补发版后核对项——桌面自动更新源（GitHub latest）未被抢占

配套 PR #16（demote-sdk-release job）的文档闭环。

PR #16 让 release.yml 自动把 `v*` Release 标为 prerelease，从而退出 GitHub
latest 竞争、使 latest 恒为 `desktop-v*`。但该 job：
  - 只在 `v*` tag 推送时运行，PR 阶段无法真跑；
  - 若 Release 尚未创建（时序竞争）会 warning 跳过而非 fail。
因此发版后仍需人工核对一次，否则问题又要等到用户报障才暴露——正是 v1.5.0
的教训（客户端 404 到被发现，中间隔了一整轮人工排查）。

新增 4.2.2 节，给出可复制的核对命令与判据：

    gh api repos/LuluDeer/AutoCodeFlow/releases/latest --jq '{tag:.tag_name, assets:(.assets|length)}'

期望 `tag` 以 `desktop-v` 开头且 `assets > 0`；若为 `v*` 则给出纠正命令
（`gh release edit <v-tag> --prerelease`），并说明纠正后客户端会自行恢复、
无需重装。

同时附三平台 channel file 的 `releases/latest/download/...` 快速自检 URL。

**本节所有命令与 URL 均已实测**（当前状态：tag=desktop-v1.5.2、assets=14、
latest.yml / latest-mac.yml / latest-linux.yml 三个均 HTTP 200）——不写未经验
证的指引。
